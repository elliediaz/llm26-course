# 7회차 사건 카드: 행동을 가르쳐라(LoRA·QLoRA)

> 6회차 `results/rag_limits.md`에 남은 '검색으로 안 고쳐진 실패'(규약대로 고르기, 형식, 답하지 않아야 할 때 답함, 계산)를 학습으로 고칠 수 있는지 잼
> 학습은 팀 서버에서 한 번에 하나만 돌림(7B LoRA 약 2~3분). 반 전체가 설정 격자를 나눠 돌리고 결과를 모아 판단함
> 판단은 `results/판단기록_s07.md`에 적음(카드 번호, 고른 것, 근거 숫자 두 개 이상). 실측 참고값과 해설은 『7회차 사건 워크북』(PDF)에 있음

## 시작 전

```bash 팀 서버 공통
source /workspace/activate.sh
cd /workspace/course && git pull
python src/resume_check.py --session 6        # 인덱스 · RAG 결과 · rag_limits.md 확인
python src/build_train_data.py --augment 300  # 학습 데이터(평가와 같은 프롬프트, 시험 문항과 비슷한 문장 제외)
```

- 학습 데이터는 평가와 같은 instruction 프롬프트로 만들어짐. 5회차에 다른 방식(fewshot)을 골랐어도 학습은 instruction으로 하고, 평가 때 비교함
- 같은 팀 서버에서 학습과 측정을 동시에 돌리지 않음(메모리 부족)
- 기준 설정 : r 16 · 학습률 2e-4 · 2에폭 · q·k·v·o 층 · bf16 본체. 설정은 한 번에 하나만 바꾸고 `--run` 이름에 바꾼 것을 적음

## 사건 1. 검색으로도 안 고쳐진 형식·판단
**상황** : RAG를 붙였는데도 틀린 문항이 남았음. 문서는 제대로 가져왔는데 규약대로 답하지 않음(우선순위·쟁점 고르기, 답하지 않아야 할 때 답함, 표기 형식)

```bash 사건 1
python src/train_lora.py --team <팀> --run r16                        # 기준 설정, 약 2~3분
python src/plot_loss.py --log results/train_log_<팀>_r16.json
python src/sweep.py adapter none adapters/<팀>/r16 --limit 10          # 학습 전후 10문항
python src/probe.py --adapter adapters/<팀>/r16 --tag lora             # 문제 입력 통과율
```

- 볼 것 : 유형별·필드별 점수(무엇이 오르고 무엇이 그대로인가), 출력 토큰, 학습 파라미터 비율, 학습 시간·메모리
- 실측 참고 : G 0.58 → 0.91(action 0.5 → 1.0), L 0.32 → 0.45(미지급액 0.2 그대로), S 0.52 → 0.65(F 0.90 → 0.70). 학습 파라미터 0.139%, Adapter 38.5MB
- **판단** : LoRA가 고친 것과 못 고친 것. RAG와 역할이 어떻게 다른지

## 사건 2. 설정 격자를 반 전체가 나눠 돌림
**상황** : 학습 설정은 많고 시간은 짧음. 팀마다 맡은 설정을 하나씩 돌려 반 전체 표를 만듦

| 설정 | 값 | 명령 예 |
|---|---|---|
| rank r | 4 · 16 · 64 | `--run r4 --r 4` |
| 학습률 | 5e-5 · 2e-4 · 1e-3 | `--run lr1e3 --lr 1e-3` |
| 에폭 | 1 · 2 · 4 | `--run ep4 --epochs 4` |
| 데이터 양 | 50건 · 전체 | `build_train_data.py --augment 300 --limit 50 --out-tag n50` → `--run n50 --data train_n50.jsonl` |
| 붙일 층 | qv · qkvo · all | `--run qv --target qv` |
| 본체 정밀도 | bf16(LoRA) · nf4(QLoRA) | `--run q4 --quant nf4` |
| 시드 | 42 · 1 · 2 | `--run r16_s1 --seed 1` |

```bash 사건 2(맡은 설정 하나)
python src/train_lora.py --team <팀> --run <이름> <옵션>
python src/sweep.py adapter none adapters/<팀>/r16 adapters/<팀>/<이름> --limit 10 --tag <이름>
```

- 볼 것 : 점수, 학습 시간, 메모리(VRAM), Adapter 크기. 결과를 반 공유 표에 적음
- 실측 참고(G) : 시드만 바꿔도 0.91 → 0.88. 학습량이 모자란 조건(50건 0.62, 1에폭 0.70, 5e-5 0.77, r 4 0.79)은 크게 떨어지고, 키운 조건(r 64, 4에폭, 전체 층)은 오르지 않음. QLoRA는 0.87에 학습 메모리 15.3 → 8.9GB
- **판단** : 우리 팀이 최종으로 쓸 설정과 근거(편차 범위 안 차이로는 고르지 않음)

## 사건 3. Loss는 내려가는데 점수가 안 오름
**상황** : 학습률을 올린 팀은 Loss가 빨리 떨어졌고, 에폭을 늘린 팀은 Loss가 0 근처까지 갔음. 그런데 점수는 그만큼 오르지 않음

```bash 사건 3
python src/plot_loss.py --log results/train_log_<팀>_lr5e5.json results/train_log_<팀>_r16.json results/train_log_<팀>_lr1e3.json --out loss_lr
python src/plot_loss.py --log results/train_log_<팀>_ep1.json results/train_log_<팀>_r16.json results/train_log_<팀>_ep4.json --out loss_ep
```

- 다른 팀이 학습한 로그는 그 팀의 `results/train_log_*.json`을 받아 같은 폴더에 두고 그림
- 볼 것 : 학습 Loss와 검증 Loss의 간격, 오르내림, 0 근처 급락. Loss가 낮다고 좋은 모델이 아님(같은 하네스로 재평가)
- 실측 참고 : 검증 Loss가 가장 낮은 학습률 1e-3(0.010)은 점수 0.90으로 2e-4(0.020, 0.91)보다 낮음. 4에폭은 Loss 0.004까지 갔지만 점수는 그대로, 시간은 두 배
- **판단** : 학습률·에폭을 정하는 기준을 한 줄

## 사건 4. 학습 데이터 정답이 일부 틀렸음
**상황** : 학습 데이터를 만든 사람이 정답 일부를 잘못 적었다는 사실을 학습 뒤에 알았음. 얼마나 망가졌을까

```bash 사건 4
python src/build_train_data.py --augment 300 --noise 0.3 --out-tag noise30     # 첫 필드(분류·쟁점·리그)의 30%를 다른 값으로
python src/train_lora.py --team <팀> --run noise30 --data train_noise30.jsonl
python src/sweep.py adapter none adapters/<팀>/r16 adapters/<팀>/noise30 --limit 10 --tag noise
```

- 볼 것 : 바뀐 필드의 점수, 다른 필드의 점수, Loss 곡선의 모양. 같은 설정을 시드만 바꾼 학습(`--seed 1`)과도 나란히 봄
- 실측 참고 : G는 category만 1.0 → 0.8. L은 오히려 0.45 → 0.52였지만 시드만 바꿔도 0.49라 편차 근처
- **판단** : 학습 데이터 점검을 어디까지 해야 하는지

## 사건 5. 어느 팀 점수가 갑자기 높아짐
**상황** : 다른 팀보다 높은 점수가 나온 팀이 있음. 축하하기 전에 확인할 것이 있음

```bash 사건 5(일부러 누수를 만들어 봄, 기록표에는 올리지 않음)
python src/build_train_data.py --augment 300 --leak --out-tag leak
python src/train_lora.py --team <팀> --run leak --data train_leak.jsonl
python src/sweep.py adapter none adapters/<팀>/r16 adapters/<팀>/leak --limit 10 --tag leak
python src/dataset_tool.py leak                                   # 시험 문항과 학습 파일의 중첩 점검
```

- 볼 것 : 누수 Adapter의 점수, 점검 도구의 중첩 건수
- 실측 참고(G) : 0.91 → 0.96. 차이가 작아 점수만으로는 알아채기 어렵고, `dataset_tool leak`이 학습 파일에서 시험 문항과 같은 예 9건을 찾음
- **판단** : 점수가 너무 좋을 때 먼저 확인할 것 세 가지

## 사건 6. 네 구성 비교와 최종 선택
**상황** : 운영 회의에서 '무엇을 붙여서 서비스할지'를 정해야 함. Baseline · RAG · LoRA · RAG+LoRA를 같은 시험지로 잼

- **판단** : 최종 구성과 근거(점수 + 지연·메모리 중 하나 이상). 8회차로 넘길 것

## 일찍 끝난 팀
- **데이터 양 곡선** : `build_train_data.py --augment 300 --limit 100 --out-tag n100`(200 · 300도 같은 방식) → `train_lora.py --team <팀> --run n100 --data train_n100.jsonl` → `sweep.py adapter none adapters/<팀>/n100 adapters/<팀>/n200 adapters/<팀>/n300 adapters/<팀>/r16 --limit 10`. 몇 건부터 기준 설정에 가까워지는지 봄
- **학습률을 크게** : `train_lora.py --team <팀> --run lr1e2 --lr 1e-2` 뒤 `plot_loss.py --log results/train_log_<팀>_r16.json results/train_log_<팀>_lr1e2.json --out loss_lr1e2`. Loss 판독 결과와 점수를 같이 봄
- **Adapter 병합** : `python src/merge_adapter.py --adapter adapters/<팀>/<고른 run>`(볼륨 여유 공간 15GB 이상) → `COURSE_MODEL_ID=adapters/<팀>/<고른 run>-merged python src/benchmark.py --name merged --no-scoreboard --limit 10`. 병합 전후 점수와 파일 크기를 비교하고, 확인 뒤 병합 폴더는 지움(서비스 배포 때 밟는 절차)
