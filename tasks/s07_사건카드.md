# 7회차 사건 카드(개인 실습): 행동을 가르쳐라(LoRA·QLoRA)

> 6회차 `results/rag_limits.md`에 남은 '검색으로 안 고쳐진 실패'(규약대로 고르기, 형식, 답하지 않아야 할 때 답함, 계산)를 학습으로 고칠 수 있는지 잼
> 6회차와 같은 번호의 개인 GPU 서버에서 혼자 진행함. 학습 한 번이 2분 안팎이라 설정을 직접 여러 개 돌릴 수 있음. 학습과 측정은 한 번에 하나만 돌림
> 필수 사건은 0 · 1 · 2 · 6 · 7, 사건 3~5는 관심에 따라 하나 이상 고름. 판단은 워크북 기록표와 `results/판단기록_s07.md`에 적음

## 시작할 때
```bash 개인 서버 터미널(새 터미널마다 첫 줄)
source /workspace/activate.sh        # 가상환경 설정과 저장소 최신화
python src/my_start.py               # 시험지 · Baseline · 인덱스 · RAG 결과가 '있음'인지
```

- 기준 설정 : r 16 · 학습률 2e-4 · 2에폭 · q·k·v·o 층 · bf16 본체. 설정은 한 번에 하나만 바꾸고 `--run` 이름에 바꾼 것을 적음
- Adapter는 `adapters/me/<run>/`에, 학습 기록은 `results/train_log_me_<run>.json`에 남음
- 학습 예시는 instruction 방식 프롬프트로 만들어짐. 6회차에 다른 방식을 저장했으면 `python src/my_start.py --strategy instruction --prompt base`로 맞추고 Baseline · RAG를 다시 잼

## 사건 1. 검색으로도 안 고쳐진 형식·판단(필수)
**상황** : RAG를 붙였는데도 틀린 문항이 남았음. 문서는 제대로 가져왔는데 규약대로 답하지 않음(우선순위·쟁점 고르기, 답하지 않아야 할 때 답함, 표기 형식)

```bash 사건 1
python src/train_lora.py --run r16                                    # 기준 설정, 약 2분
python src/plot_loss.py --log results/train_log_me_r16.json
python src/sweep.py adapter none adapters/me/r16 --limit 10            # 학습 전후 10문항
python src/probe.py --adapter adapters/me/r16 --tag lora               # 문제 입력 통과율
```

- 볼 것 : 유형별·필드별 점수(무엇이 오르고 무엇이 그대로인가), 출력 토큰, 학습 파라미터 비율, 학습 시간·메모리
- 실측 참고 : G 0.58 → 0.91(action 0.5 → 1.0), L 0.32 → 0.45(미지급액 0.2 그대로), S 0.52 → 0.65(F 0.90 → 0.70). 학습 파라미터 0.139%, Adapter 38.5MB
- **판단** : LoRA가 고친 것과 못 고친 것. RAG와 역할이 어떻게 다른지

## 사건 2. 설정 하나를 골라 바꿔 봄(필수)
**상황** : 학습 설정은 많고 시간은 짧음. 시드만 바꾼 학습으로 편차를 먼저 재고, 관심 있는 설정 하나를 골라 값 두 개를 돌려 봄

| 고를 설정 | 값 두 개의 옵션 |
|---|---|
| rank r | `--run r4 --r 4` · `--run r64 --r 64` |
| 학습률 | `--run lr5e5 --lr 5e-5` · `--run lr1e3 --lr 1e-3` |
| 에폭 | `--run ep1 --epochs 1` · `--run ep4 --epochs 4` |
| 데이터 양 | `build_train_data.py --augment 300 --limit 50 --out-tag n50` 뒤 `--run n50 --data train_n50.jsonl`(200건도 같은 방식) |
| 붙일 층 | `--run qv --target qv` · `--run all --target all` |
| 본체 정밀도 | `--run q4 --quant nf4` |

```bash 사건 2
python src/train_lora.py --run r16_s1 --seed 1                        # 같은 설정, 다른 시드(편차 폭)
python src/train_lora.py --run <이름> <옵션>                           # 고른 설정의 값 하나
python src/train_lora.py --run <이름2> <옵션2>                         # 같은 설정의 다른 값
python src/sweep.py adapter none adapters/me/r16 adapters/me/r16_s1 adapters/me/<이름> adapters/me/<이름2> --limit 10 --tag grid
```

- 볼 것 : 점수, 학습 시간, 메모리(VRAM), Adapter 크기. 시드 차이보다 작은 차이로는 고르지 않음
- 실측 참고(G) : 시드만 바꿔도 0.91 → 0.88. 학습량이 모자란 조건(50건 0.62, 1에폭 0.70, 5e-5 0.77, r 4 0.79)은 크게 떨어지고, 키운 조건(r 64, 4에폭, 전체 층)은 오르지 않음. QLoRA는 0.87
- **판단** : 내 최종 설정과 근거

## 사건 3. Loss는 내려가는데 점수가 안 오름(선택)
**상황** : 학습률을 올리면 Loss가 빨리 떨어지고, 에폭을 늘리면 Loss가 0 근처까지 감. 그런데 점수는 그만큼 오르지 않음

```bash 사건 3(사건 2에서 이미 학습한 run은 다시 학습하지 않음)
python src/train_lora.py --run lr5e5 --lr 5e-5
python src/train_lora.py --run lr1e3 --lr 1e-3
python src/plot_loss.py --log results/train_log_me_lr5e5.json results/train_log_me_r16.json results/train_log_me_lr1e3.json --out loss_lr
python src/train_lora.py --run ep1 --epochs 1
python src/train_lora.py --run ep4 --epochs 4
python src/plot_loss.py --log results/train_log_me_ep1.json results/train_log_me_r16.json results/train_log_me_ep4.json --out loss_ep
python src/sweep.py adapter none adapters/me/lr5e5 adapters/me/r16 adapters/me/lr1e3 --limit 10 --tag lr
```

- 볼 것 : 학습 Loss와 검증 Loss의 간격, 오르내림, 0 근처 급락. Loss가 낮다고 좋은 모델이 아님(같은 하네스로 재평가)
- 실측 참고 : 검증 Loss가 가장 낮은 학습률 1e-3(0.010)은 점수 0.90으로 2e-4(0.020, 0.91)보다 낮음. 4에폭은 Loss 0.004까지 갔지만 점수는 그대로, 시간은 두 배
- **판단** : 학습률·에폭을 정하는 기준을 한 줄

## 사건 4. 학습 데이터 정답이 일부 틀렸음(선택)
**상황** : 학습 데이터를 만든 사람이 정답 일부를 잘못 적었다는 사실을 학습 뒤에 알았음. 얼마나 망가졌을까

```bash 사건 4
python src/build_train_data.py --augment 300 --noise 0.3 --out-tag noise30     # 첫 필드(분류·쟁점·리그)의 30%를 다른 값으로
python src/train_lora.py --run noise30 --data train_noise30.jsonl
python src/sweep.py adapter none adapters/me/r16 adapters/me/noise30 --limit 10 --tag noise
```

- 볼 것 : 바뀐 필드의 점수, 다른 필드의 점수, Loss 곡선의 모양. 사건 2의 시드 학습(`r16_s1`)과도 나란히 봄
- 실측 참고 : G는 category만 1.0 → 0.8. L은 오히려 0.45 → 0.52였지만 시드만 바꿔도 0.49라 편차 근처
- **판단** : 학습 데이터 점검을 어디까지 해야 하는지

**상황** : 학습 파일을 바꾼 뒤 점수가 눈에 띄게 높아졌음. 결과로 채택하기 전에 확인할 것이 있음

## 자유 실험(약 20분)
- **내 학습 문항 넣기** : `data/<도메인>/my_train_items.jsonl`에 `train_seed.jsonl`과 같은 형식으로 10건 안팎을 씀 → `python src/build_train_data.py --augment 300 --my data/<도메인>/my_train_items.jsonl --out-tag mine` → `python src/train_lora.py --run mine --data train_mine.jsonl` → `python src/sweep.py adapter none adapters/me/r16 adapters/me/mine --limit 10 --tag mine`
- **QLoRA와 bf16** : `python src/train_lora.py --run q4 --quant nf4` 뒤 `sweep.py adapter`로 학습 시간 · VRAM · 점수 비교
- **데이터 양 곡선** : `build_train_data.py --augment 300 --limit 100 --out-tag n100`(200 · 300도 같은 방식) → `train_lora.py --run n100 --data train_n100.jsonl` → `sweep.py adapter none adapters/me/n100 adapters/me/n200 adapters/me/n300 adapters/me/r16 --limit 10 --tag curve`
- **학습률을 크게** : `train_lora.py --run lr1e2 --lr 1e-2` 뒤 `plot_loss.py --log results/train_log_me_r16.json results/train_log_me_lr1e2.json --out loss_lr1e2`
- **다른 모델로 LoRA** : `COURSE_MODEL_ID=Qwen/Qwen3-8B python src/train_lora.py --run qwen8b` 뒤 `COURSE_MODEL_ID=Qwen/Qwen3-8B python src/sweep.py adapter none adapters/me/qwen8b --limit 10 --tag qwen`. 11/22 실측은 학습 1.7분, 0.61 → 0.89
- **Adapter 병합** : `python src/merge_adapter.py --adapter adapters/me/<고른 run>`(볼륨 여유 15GB 이상, `du -sh /workspace`로 확인) → `COURSE_MODEL_ID=adapters/me/<고른 run>-merged python src/benchmark.py --name merged --no-scoreboard --limit 10` → 확인 뒤 `rm -rf adapters/me/<고른 run>-merged`
