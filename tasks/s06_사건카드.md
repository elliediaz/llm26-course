# 6회차 사건 카드(개인 실습): 근거 문서를 붙여라(RAG와 벡터DB)

> 오늘부터 개인 GPU 서버에서 혼자 진행함. 모델은 바꾸지 않고 프롬프트에 근거 문서를 붙여(RAG) K(지식형) 점수가 얼마나 오르는지 잼
> 필수 사건은 0 · 1 · 6 · 7, 사건 2~5는 관심에 따라 둘 이상 고름. 선택 사건은 15분 단위로 끊음
> 판단은 워크북 기록표와 `results/판단기록_s06.md`에 적음(고른 것, 근거 숫자 두 개 이상). 실측 참고값과 해설은 『6회차 개인 실습 워크북』(PDF)에 있음

## 시작할 때
```bash 개인 서버 터미널(새 터미널마다 첫 줄)
source /workspace/activate.sh        # 가상환경 설정과 저장소 최신화
python src/my_start.py               # 내 설정과 진행 상태
```

- 접속 주소 : 저장소 `ACCESS.md`에서 카드에 적힌 서버 번호 줄. 비밀번호는 카드
- LLM이 들어가는 측정은 한 번에 하나만 돌림. 측정이 도는 동안 다른 터미널에서 문서와 코드를 읽음

## 사건 0. 내 서버 준비와 개인 Baseline(필수)
**상황** : 5회차의 시험지와 Baseline은 팀 서버에 있음. 내 도메인을 정하고 개인 시험지와 Baseline을 내 서버에서 새로 만듦

```bash 사건 0
python src/check_gpu.py                                    # GPU 이름 · 메모리 · 받아 둔 모델
python src/my_start.py --domain <G|L|S> --seat <내 번호>     # 예 : 카드가 P07이면 --domain L --seat 7
python src/my_start.py --strategy fewshot --shots 2 --prompt prompts/s05/형식엄수.txt   # (선택) 5회차 방식 · 규칙 파일
python src/benchmark.py --runs 2                           # Baseline 30문항 두 번(약 2분)
python src/scoreboard.py                                   # 기록표 1행
python src/index_builder.py                                # 인덱스 두 가지(약 1분)
```

- 도메인 : G 게임 운영 · L 알바 급여 정산 · S 스포츠 기록실. `data/<도메인>/README.md`와 `corpus/` 문서를 읽고 고름
- 개인 시험지 30건 = 공통 시드 10건 + 문항 풀에서 내 번호로 뽑은 20건. 옆 사람 · 실측 표와 비교할 때는 `--limit 10` 값을 봄
- **판단** : 고른 도메인과 이유, Baseline 점수와 가장 낮은 유형

## 사건 1. 정책 문서를 봤으면 맞혔을 문의(필수)
**상황** : Baseline에서 틀린 문항을 열어 보니 운영정책 · 사업장 정보 · 기록 문서를 봐야 알 수 있는 내용이 대부분이었음. 문서를 붙이면 얼마나 오르나

```bash 사건 1
python src/sweep.py mode base rag --limit 10                         # 검색 전후 10문항(약 1분)
python src/rag.py --q "<Baseline에서 틀린 문항 하나>" --show-prompt     # 모델에 실제로 들어간 근거 문서
python src/rag.py --q "<같은 문항>" --no-rag                          # 같은 질문, 검색 없이
```

- 볼 것 : 유형별 점수(K가 오르는가, R · F는 그대로인가), 검색 적중, 입력 토큰과 지연
- 실측 참고 : K가 G 0.47 → 0.75, S 0.23 → 0.95로 올랐지만 L은 0.23 → 0.28. S의 F는 0.90 → 0.40으로 떨어짐. 입력은 2.4~3.6배
- **판단** : RAG를 붙일 가치가 있는지, 대가(입력 토큰 · 지연 · 떨어진 유형)와 함께 한 줄

## 사건 2. 검색이 엉뚱한 문서를 가져옴(선택)
**상황** : 근거 문서를 붙였는데 질문과 관계없는 문서가 올라온 문항이 있음. 문서를 자르는 크기(Chunking)가 검색 품질을 바꿈

```bash 사건 2(LLM 없이 검색만 잼)
python src/index_builder.py --stats                                   # 두 전략의 청크 수 · 길이
python src/retrieval_sweep.py size 200 500 1000 2000                  # 청크 크기(약 40초)
python src/retrieval_sweep.py overlap 0 100 250 --size 500            # 중첩
python src/retrieval_sweep.py strategy fixed sentence                 # 분할 방식
```

- 볼 것 : Recall@1 · 3 · 5, MRR, 청크 수, 유형별 Recall@3
- 실측 참고 : 200자로 자르면 세 도메인 모두 떨어짐. 문서보다 크게 잘라도 청크 수가 문서 수 아래로 줄지 않아 거의 그대로
- **판단** : 고른 분할 방식과 크기, 근거. `src/config.py`의 `CHUNK` · `CHUNK_STRATEGY`에 적고 `python src/index_builder.py`

## 사건 3. 이름과 숫자가 든 질문에서 놓침(선택)
**상황** : '서리칼날', 'v1.4', '모퉁이분식', '한빛시리즈 4차전'처럼 이름과 숫자가 핵심인 질문에서 검색이 자주 빗나감

```bash 사건 3(LLM 없이 검색만 잼)
python src/retrieval_sweep.py embed nlpai-lab/KURE-v1 BAAI/bge-m3 keyword    # 임베딩 둘과 키워드(BM25)
python src/retrieval_sweep.py hybrid 0 0.3 0.5 0.7 1                          # 키워드 비중(0 벡터만 ~ 1 키워드만)
python src/hybrid_search.py --strategy sentence                               # 순위 합치기(RRF) 방식
```

- 볼 것 : 키워드만 쓸 때와 벡터만 쓸 때 어느 유형이 강한지, 섞었을 때 더 나은 지점이 있는지
- 실측 참고 : 키워드는 F(정책 · 해설 문서) 적중을 올리지만 L은 키워드만 쓰면 1등을 거의 못 맞힘. 키워드 0.3 섞기가 세 도메인 모두 가장 좋음
- **판단** : 내 도메인에 맞는 검색 방식과 근거(유형별 이득 · 손해)

## 사건 4. 문서를 많이 넣었더니 느려지고 틀림(선택)
**상황** : 정답 문서가 들어갈 확률을 높이려고 검색 문서 수를 8개로 늘렸더니 지연이 늘고 점수는 그대로이거나 떨어졌음

```bash 사건 4
python src/sweep.py top_k 1 2 4 8 --mode rag --limit 10                      # 약 2분
python src/sweep.py context_tokens 300 800 1500 3000 --mode rag --limit 10   # 약 2분
```

- 볼 것 : 점수, 검색 적중, 입력 토큰, p50 지연. 적중이 오르는데 점수가 오르지 않는 지점
- 실측 참고 : G · L은 적중이 0.2~0.5에서 0.6~0.9로 올라도 점수는 거의 그대로. S는 2개에서 가장 높음. 상한 800 이상은 G · L에서 차이 없음
- **판단** : `config.RAG_TOP_K` · `CONTEXT_MAX_TOKENS`로 고른 값과 근거

## 사건 5. 새 문서가 나왔다(선택)
**상황** : 기준일 뒤에 새 문서가 나왔음. G 11/19 점검 공지와 겨울 축제, L 달빛편의점 직원 수 변경(2027-03-01부터 6명), S 월드 인비테이셔널 결승 결과. 모델을 다시 학습하지 않고 답을 바꿀 수 있나

```bash 사건 5
python src/rag.py --q "<새 문서와 관련된 질문>"                       # 전
python src/index_builder.py --strategy <전략> --with-updates           # 새 문서를 넣어 인덱스만 다시(약 10초)
python src/rag.py --q "<같은 질문>"                                    # 후
python src/index_builder.py --strategy <전략>                          # 시험지 측정 전에 원래대로
```

| 도메인 | 질문 예 |
|---|---|
| G | 겨울 성좌 축제에서 성좌의 등불 받으려면 별빛 청크 몇 개 모아야 해요? |
| L | 한빛로 달빛편의점에서 2027년 3월 2일부터 4주 동안 주 3일, 20시부터 다음 날 2시까지 6시간씩 일했어요. 시급 10,700원이고 주휴수당은 받았는데 야간수당은 따로 없었어요. 덜 받은 돈이 있나요? |
| S | 2026 월드 인비테이셔널 우승팀이 어디예요? |

- 실측 참고 : G · S는 답이 정답으로 바뀜. L은 쟁점은 '가산미지급'으로 바뀌었지만 금액은 0원 그대로(정답 256,800원)
- **판단** : 재학습 없이 바뀐 것과 바뀌지 않은 것. 자주 바뀌는 지식을 어디에 둬야 하는지

## 사건 6. 검색은 맞았는데 답이 틀림(필수)
**상황** : 30문항을 RAG로 재 보니 오른 문항도 있지만 여전히 틀린 문항이 있음. 검색 탓인지 생성 탓인지 나눠야 다음 처방(7회차)이 정해짐

```bash 사건 6
python src/benchmark.py --mode rag                   # 30문항 RAG(약 2분), 기록표 2행
python src/rag.py --diagnose results/rag.json        # 원인별 분류 → results/rag_limits.md
python src/probe.py --tag base                       # 문제 입력 16건, 근거 문서 없이
python src/probe.py --mode rag --tag rag             # 같은 16건, 근거 문서를 붙여서
```

- 볼 것 : '검색 실패'(정답 문서를 못 가져옴)와 '생성 실패'(가져왔는데 틀림)의 개수, 틀린 필드, 문제 입력 통과율의 변화
- 실측 참고 : G는 틀린 6건 중 3건이 검색 실패, L은 8건 중 7건이 생성 실패(금액 · 조문). 문서를 붙이자 L은 무관 질문에도 답하기 시작함
- **판단** : 검색으로 고칠 것과 학습(7회차) · 도구(8회차)로 넘길 것

## 자유 실험(약 25분)
- **내 문서 넣기** : 내가 지은 가상 문서 한 건을 `data/<도메인>/corpus_updates/my_doc.md`에 쓰고 `updates_manifest.json`에 한 줄(doc_id · title · file)을 더함 → `python src/index_builder.py --strategy <전략> --with-updates` → 그 문서로만 답할 수 있는 질문을 `rag.py --q`로 확인. 끝나면 `git checkout data/<도메인>/corpus_updates/updates_manifest.json` 뒤 인덱스를 원래대로 만듦
- **재순위화** : `python src/rerank.py`. 1차 검색 후보 20개를 질문과 함께 다시 읽어 순위를 고침. Recall@1 · MRR이 늘어난 지연만큼 오르는지 봄
- **근거 문장 찾기** : 맞힌 문항 둘, 틀린 문항 둘을 `rag.py --q "<문항>" --show-prompt`로 돌리고, 답의 근거가 된 문장을 근거 문서에서 찾아 판단 기록에 옮겨 적음
- **새 모델 내려받아 비교** : `hf download Qwen/Qwen3-4B` → `python src/sweep.py model skt/A.X-4.0-Light Qwen/Qwen3-4B --mode rag --limit 10`. 받기 전에 `du -sh /workspace`로 지금까지 쓴 용량 확인(볼륨 100GB)
- **다른 도메인으로 한 번 더** : `COURSE_DOMAIN=S python src/index_builder.py` → `COURSE_DOMAIN=S python src/sweep.py mode base rag --limit 10`
- **동시 실행 지연** : 터미널 두 개에서 동시에 `python src/benchmark.py --mode rag --limit 10 --no-scoreboard`를 돌려 p50 · p95를 혼자 돌린 값과 비교
