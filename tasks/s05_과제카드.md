# 5회차 과제 카드: 같은 잣대로 재는 도구 만들기

> 1회차 명제와의 연결: 팀 과제 JSON의 필드는 분류(category·action·priority·is_intended·patch) 아니면 추출(entity·fact)임. 채점기는 필드마다 "맞았는가"를 재고, 그 가중 평균이 Task Accuracy가 됨

## A. 팀 문항 20건 작성·점검·병합 (필수, 팀, 22분, 실습 1 ③)

```bash
cp data/<도메인>/team_item_template.json data/<도메인>/team_items.json
# 1인 4~5건씩 작성(유형 할당: K 8 · R 7 · F 5)
python src/dataset_tool.py check
python src/dataset_tool.py merge
```

- 완료 기준: `check` 통과, `test_dataset.json` 30건(시드 10 + 팀 20)
- 문항 작성 규칙: 정답이 하나로 정해질 것, 가상 사례만, 시드 문항과 문장 틀이 겹치지 않을 것

## B. 필드별로 보기: 1회차 분류기 vs LLM (팀, 결과 검증 중 5분)

```bash
python src/field_report.py                 # results/base.json 기준
```

- 표에서 "같은 문항: LLM"과 "같은 문항: 1회차 분류기" 열을 비교함(시드 10건)
- 팀 질문
  1. 한 필드만 맞히는 전용 분류기가 LLM보다 높은 필드가 있는가. 있다면 왜 LLM을 쓰는가
  2. 가장 약한 필드는 분류인가 추출인가 → 6회차(RAG)와 7회차(LoRA) 중 어디에서 오를지 예측해 기록표 목표치에 반영

## C. 엄격 채점과 느슨한 채점 (개인 도전)

```bash
python src/scorer.py results/fmt_instruction.json --mode strict
```

- 코드 펜스(```)·앞뒤 설명문이 붙은 출력이 엄격 모드에서 몇 건 탈락하는지 셈
- 질문: 9회차 API가 이 출력을 받는다면 어느 모드가 실제 서비스에 가까운가

## D. LLM에게 채점을 맡기면 (개인 도전)

```bash
python src/judge.py results/base.json --field fact
```

- fact 필드(근거 한 줄)에서 규칙 채점과 LLM 채점이 다른 문항을 찾아 이유를 적음. 같은 명령을 두 번 실행해 LLM 채점이 흔들리는지 확인함
