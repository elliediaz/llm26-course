## 해보기 ①

### A. MiniGPT 조정하기 (필수)

- 기본 코드: `src/mini_transformer.py`(디코더 블록 × 4, 슬라이드 '디코더 블록' 그림과 같은 구조)
- 데이터: `data/G/corpus/`(가상 RPG '프로젝트 루멘' 문서 63개: 장비·영웅·이벤트·공지·패치노트·운영정책, 강사 제작, 18,744자)
- 하는 일: 앞 글자들을 보고 다음 글자 하나를 고르는 **423칸 분류**를 1.5분 동안 반복 학습. 1회차 실습 C와 같은 학습 루프
- 기본 결과(개인 CPU 서버, 1.5분): 466스텝 · 학습 손실 0.235 · 검증 손실 2.829(가장 낮았을 때 2.746, 300스텝) · 한 번 약 94초
- 실행할 때마다 `results/mini_gpt_runs.md`에 한 줄씩 쌓이고, 손실 곡선은 `results/fig/mini_gpt_loss.png`에 그려짐

| 바꿔 볼 것 | 명령 예 | 생각해 볼 질문 |
|---|---|---|
| 층 수(블록 N) | `--layers 2` / `--layers 8` | 같은 1.5분에 스텝 수가 어떻게 달라지나. 깊으면 무조건 좋아지나 |
| 숫자 개수(d_model) | `--d-model 64` / `--d-model 256` | 파라미터가 몇 배가 되나(블록 하나 ≈ 12 × d²) |
| 헤드 수 | `--heads 1` / `--heads 8` | 파라미터는 그대로인데 결과가 달라지나. 왜 파라미터가 같은가 |
| 문맥 길이 | `--context 32` | 한 번에 보는 글자가 줄면 생성 결과가 어떻게 바뀌나 |
| 학습률 | `--lr 0.0003` / `--lr 0.01` | 손실이 내려가는 속도 |
| 드롭아웃 | `--dropout 0.2` | 학습 손실과 검증 손실의 차이가 줄어드나 |
| 학습 시간 | `--train 3` | 더 오래 학습하면 검증 손실도 계속 좋아지나 |
| **학습 글 바꾸기** | `--corpus nsmc` | 영화 리뷰 3만 건(1회차 실습 C 데이터)으로 학습하면 무엇을 쓰나 |

- 힌트 1: **학습 손실**은 외운 글에서, **검증 손실**은 각 문서 끝 10%(학습에 안 쓴 부분)에서 잰 값임. 학습 손실만 내려가고 검증 손실이 오르면 글을 외우기 시작한 것(과적합)
- 힌트 2: 시간을 1.5분으로 묶었으므로 큰 모델은 스텝을 적게 밟음. "크기"와 "학습량"이 함께 바뀐다는 점을 기록표 '이유' 칸에 반영할 것
- 힌트 3: 무작위로 찍을 때의 손실은 ln(423) ≈ 6.05임. 이보다 얼마나 낮아졌는지가 배운 정도
- 힌트 4: 생성 예시는 greedy(항상 1등)와 T 0.8(확률대로) 두 줄이 나옴. 같은 모델에서 고르는 법만 다름. 실습 2의 2-T2와 같은 이야기
- 도전: `Block` 클래스의 MLP를 `d → 2d → d`로 줄이면 파라미터와 결과가 어떻게 바뀌나

### E. KV Cache 크기 손으로 계산하기 (필수, 개인)

- 식: 캐시 크기(바이트) = 2(K·V) × 층 수 × KV 헤드 수 × 헤드 차원 × 토큰 수 × 2(bf16 한 값 = 2바이트)
- 설정값 확인: `python -c "from transformers import AutoConfig as A; c=A.from_pretrained('Qwen/Qwen3-0.6B'); print(c.num_hidden_layers, c.num_key_value_heads, c.head_dim)"`

| 모델 | 층 | KV 헤드 | 헤드 차원 | 토큰당(바이트) | 8,192토큰 | 가중치(bf16) |
|---|---|---|---|---|---|---|
| Qwen3-0.6B | | | | | | 약 1.2GB |
| A.X-4.0-Light(메인 LLM) | | | | | | 약 15GB |

- 확인: `python src/kv_cache_bench.py --lengths 128 512`의 '캐시 크기' 열과 같은 식인지 비교
- 질문 1: GQA(KV 헤드를 Q 헤드보다 적게 둠)가 없으면 캐시는 몇 배가 되나
- 질문 2: 24GB GPU에 A.X-4.0-Light(약 15GB)를 올리면 캐시에 쓸 수 있는 메모리로 몇 토큰까지 넣을 수 있나(다른 사용량은 1GB로 가정). 6회차에 검색 문서를 몇 개까지 넣을 수 있는지의 근거가 됨

### F. LLM을 분류기로 쓰기: 후보 라벨의 확률 비교 (선택)

- 생성하지 않고도 LLM으로 분류할 수 있음: 프롬프트 뒤에 후보 라벨("버그", "결제", "밸런스" …)을 하나씩 붙여 각 라벨 토큰들의 로그확률 합을 비교하고 가장 높은 것을 고름
- `typing/s01/t3_next_token.py`를 복사해 `my_label_score.py`를 만들고 아래 뼈대를 채움

```python
labels = ["버그", "밸런스", "결제", "계정", "이벤트", "제재", "기타"]
prompt = "문의: 결제했는데 다이아가 안 들어왔어요\n분류:"
for lab in labels:
    ids = tok(prompt + " " + lab, return_tensors="pt").to(DEV)
    n_prompt = len(tok(prompt)["input_ids"])
    # logits의 각 위치에서 '다음에 실제로 온 토큰'의 log softmax 값을 라벨 구간만 더함
    ...
```

- 1회차 해보기 E(`ticket_classifier.py`, category 시드 10건 정확도 0.80)와 비교해 기록표 한 줄로 남김
- 힌트: 라벨마다 토큰 수가 다르면 합이 불리해짐. 합과 평균을 둘 다 봄(막히면 강사·TA에게 예시 답을 요청)
